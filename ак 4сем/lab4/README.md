## Язык программирования

В качестве языка программирования используется учебный ассемблер.

Ассемблер поддерживает:

- метки;
- секции;
- директиву .org;
- константы через .equ;
- размещение слов через .word;
- резервирование памяти через .space;
- C-строки через .cstr;
- комментарии через ;.

Пример программы:

asm .equ OUT, 0xFF01  .section text .org 0  _start:     print_cstr msg     halt  .section data .org 100  msg:     .cstr "Hello, world!\n" 

### Синтаксис

Упрощённая форма синтаксиса:

text program       ::= line* line          ::= label | directive | instruction | empty label         ::= identifier ":" directive     ::= ".section" section_name                 | ".org" number                 | ".equ" identifier "," number                 | ".word" value                 | ".space" number                 | ".cstr" string instruction   ::= mnemonic operand_list? operand_list  ::= operand | operand "," operand operand       ::= register | immediate | memory | label register      ::= "r0" | "r1" | "r2" | "r3" memory        ::= "[" register "]" | "[" label "]" | "[" number "]" 

### Семантика

Программа состоит из секций text и data.

Секция text содержит инструкции.  
Секция data содержит статические данные: числа, строки, буферы.

Директива .org задаёт адрес размещения следующих инструкций или данных.

Метки используются как символические имена адресов. Например:

asm loop:     add r0, 1     jmp loop 

Константы задаются через .equ:

asm .equ IN, 0xFF00 .equ OUT, 0xFF01 

C-строки задаются через .cstr. Каждый символ строки занимает одно машинное слово, после последнего символа автоматически добавляется нулевое слово.

Например:

asm msg:     .cstr "Hi" 

будет размещено в памяти как:

text 'H' 'i' 0

## Организация памяти

Используется фон-неймановская архитектура: инструкции и данные находятся в общей памяти.

Память состоит из 65536 машинных слов.

text +------------------------------+ | 0x0000                       | |                              | | instructions                 | |                              | | static data                  | | strings                      | | buffers                      | |                              | | 0xFF00 input port            | | 0xFF01 output port           | +------------------------------+ 

Размер машинного слова — 32 бита.

### Регистры

В модели процессора используются следующие регистры:

| Регистр | Назначение |
|---|---|
| PC | счётчик команд |
| IR | регистр инструкции |
| MAR | регистр адреса памяти |
| MDR | регистр данных памяти |
| R0–R3 | регистры общего назначения |
| ZF | флаг нуля |
| NF | флаг отрицательного результата |
| CF | флаг переноса |

### Memory-mapped I/O

Ввод-вывод реализован через отображение портов в память.

| Адрес | Назначение |
|---|---|
| 0xFF00 | порт ввода |
| 0xFF01 | порт вывода |

Чтение из 0xFF00 возвращает следующий символ из входного потока.

Запись в 0xFF01 добавляет символ в выходной буфер.

Пример:

asm mov r0, [IN] mov [OUT], r0

## Система команд

Архитектура относится к CISC, потому что:

- инструкции имеют переменную длину;
- инструкции могут работать с регистрами, памятью и непосредственными значениями;
- есть сложные инструкции, выполняющие много действий внутри одной команды;
- сложные инструкции реализуются микрокодом.

### Набор инструкций

| Инструкция | Описание |
|---|---|
| halt | остановка процессора |
| mov dst, src | пересылка данных |
| add dst, src | сложение |
| sub dst, src | вычитание |
| mul dst, src | умножение |
| div dst, src | целочисленное деление |
| mod dst, src | остаток от деления |
| cmp a, b | сравнение |
| jmp label | безусловный переход |
| jz label | переход, если ZF = 1 |
| jnz label | переход, если ZF = 0 |
| jg label | переход, если больше |
| jl label | переход, если меньше |
| print_cstr addr | печать C-строки |
| read_cstr addr, max_len | чтение C-строки |
| print_num operand | печать числа |

### Режимы адресации

Поддерживаются следующие режимы адресации:

| Вид | Пример | Описание |
|---|---|---|
| регистровая | r0 | значение в регистре |
| непосредственная | 10 | константа в коде |
| прямая память | [x] | значение по адресу метки |
| косвенная память | [r0] | значение по адресу из регистра |
| метка | msg | адрес метки |

## Представление машинного кода

Машинный код сохраняется в настоящий бинарный файл .bin.

Машинное слово имеет размер 32 бита и записывается в little-endian формате.

Формат заголовочного слова инструкции:

text 31........24 23....20 19....16 15....12 11.....8 opcode       op1_t   op1_r   op2_t   op2_r 

Инструкции имеют переменную длину.

Например:

asm halt 

занимает одно машинное слово.

asm mov r0, 10 

занимает два машинных слова:

text слово 1: заголовок инструкции слово 2: непосредственное значение 10 

asm print_cstr msg 

занимает два машинных слова:

text слово 1: заголовок инструкции слово 2: адрес строки msg 

Кроме .bin, транслятор создаёт отладочный .hex файл с человекочитаемым представлением машинного кода.

## Транслятор

Транслятор реализован в файле translator.py.

Интерфейс командной строки:

bash python3 translator.py examples/hello.asm build/hello.bin 

На вход подаётся:

- файл с исходным кодом на ассемблере;
- путь для сохранения бинарного машинного кода.

На выходе создаются:

- .bin — бинарный машинный код;
- .hex — отладочное текстовое представление.

Транслятор работает в два прохода.

### Первый проход

На первом проходе транслятор:

- читает исходные строки;
- удаляет комментарии;
- обрабатывает .equ;
- определяет текущую секцию;
- учитывает .org;
- собирает таблицу меток;
- вычисляет адреса инструкций и данных.

### Второй проход

На втором проходе транслятор:

- кодирует инструкции;
- размещает данные;
- подставляет адреса меток;
- формирует массив машинных слов;
- записывает .bin;
- записывает .hex.

## Модель процессора

Модель процессора реализована в файле machine.py.

Интерфейс командной строки:

bash python3 machine.py build/hello.bin python3 machine.py build/cat.bin input.txt --log build/cat.log python3 machine.py build/pipeline_demo.bin --pipeline --log build/pipeline_demo_pipe.log 

Модель включает:

- память;
- регистры;
- ALU;
- flags;
- DataPath;
- микрокодное Control Unit;
- input buffer;
- output buffer;
- tick-by-tick журнал.

### DataPath

DataPath отвечает за хранение и передачу данных:

- чтение и запись памяти;
- чтение из input port;
- запись в output port;
- регистры общего назначения;
- внутренние регистры процессора;
- флаги.

### ControlUnit

ControlUnit управляет исполнением программы.

Исполнение происходит не целыми инструкциями, а микрокомандами.

Типичный цикл выборки инструкции:

text FETCH_ADDR FETCH_READ FETCH_LATCH DECODE 

После декодирования выбирается микропрограмма конкретной инструкции.

## Микрокод

Вариант требует микрокодное устройство управления.

Каждая инструкция ISA разворачивается в последовательность микроопераций.

Пример для add r0, 1:

text FETCH_ADDR FETCH_READ FETCH_LATCH DECODE READ_OPERAND ALU_ADD WRITE_REG 

Пример для print_cstr msg:

text FETCH_ADDR FETCH_READ FETCH_LATCH DECODE LOAD_MEM CHECK_ZERO OUTPUT_CHAR INC_PTR LOAD_MEM CHECK_ZERO ... 

Инструкция print_cstr является CISC-инструкцией, потому что одна инструкция выполняет цикл по памяти и печатает строку до нулевого символа.

Фрагмент журнала:

text tick=000005 pc=0002 ir=0d000000 micro=LOAD_MEM mar=0064 ... tick=000006 pc=0002 ir=0d000000 micro=CHECK_ZERO mar=0064 ... tick=000007 pc=0002 ir=0d000000 micro=OUTPUT_CHAR mar=0064 ... tick=000008 pc=0002 ir=0d000000 micro=INC_PTR mar=0064 ...

## Pipeline

В рамках усложнения реализован упрощённый конвейер из трёх стадий:

text IF — Instruction Fetch ID — Instruction Decode EX — Execute microprogram 

Конвейерный режим включается флагом:

bash python3 machine.py build/pipeline_demo.bin --pipeline 

Из-за CISC-инструкций переменной длины и микрокодной стадии исполнения конвейер имеет ограничения:

- сложные инструкции занимают EX несколько тактов;
- при переходах выполняется flush неверно выбранных инструкций;
- IF и ID не всегда могут эффективно перекрываться с EX.

В журнале конвейерного исполнения выводятся стадии:

text IF=pc:0010 ID=- EX=print_cstr:LOAD_MEM 

Пример сравнения для pipeline_demo:

| Режим | Результат | Число строк лога |
|---|---:|---:|
| без pipeline | 201 | около 8086 |
| с pipeline | 201 | около 8087 |

Ускорение на данной программе практически отсутствует из-за частых переходов и микрокодной EX-стадии. При этом в модели отражена структура IF/ID/EX и механизм flush при переходах.

## Алгоритмы

### hello

Печатает строку:

text Hello, world! 

### cat

Считывает входной поток и печатает его обратно.

Пример:

text input:  abc output: abc 

### hello_user_name

Запрашивает имя пользователя и печатает приветствие.

text What is your name? Hello, Alice! 

### sort

Сортирует список однозначных чисел.

Формат ввода:

text 514325 

Первый символ — количество элементов.  
Далее идут элементы массива.

Для примера:

text 5 1 4 3 2 5 

Результат:

text 12345 

### double_precision

Демонстрирует арифметику двойной точности на 32-битной машине.

64-битное число представляется как пара:

text high:low 

Пример:

text 0x00000000:0xFFFFFFFF + 1 = 0x00000001:0x00000000 

Вывод программы:

text high=1 low=0 result=1:0 

### prob1

Реализован алгоритм Project Euler Problem 4.

Задача: найти наибольший палиндром, являющийся произведением двух трёхзначных чисел.

Результат:

text 906609
